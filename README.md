# 매입 계약 현황 대시보드

매입 계약 진행 현황(엑셀)을 웹페이지로 보여주는 내부 공유용 대시보드입니다.
빌드 과정이 없는 정적 페이지(`index.html` + `data.js`)입니다.

> ⚠️ 계약·거래처 정보가 들어 있으므로 저장소는 반드시 **Private** 으로 유지하세요.

## 보는 법
`index.html` 을 브라우저로 열면 됩니다. (서버 불필요)

## 데이터 갱신 방법
1. 엑셀(매입 계약 진행 현황)을 최신으로 수정합니다.
2. 아래 명령으로 `data.js` 를 다시 만듭니다.
   ```bash
   pip install openpyxl
   python3 scripts/build_data.py "엑셀파일.xlsx"
   ```
3. 변경사항을 커밋하고 올립니다.
   ```bash
   git add data.js
   git commit -m "계약 현황 업데이트"
   git push
   ```

엑셀 원본(`*.xlsx`)은 `.gitignore` 로 제외되어 있어 저장소에는 올라가지 않습니다.
(단, `data.js` 안에 엑셀 내용이 그대로 들어가므로 저장소 공개 범위에 유의하세요.)

## 자동 업데이트 (OneDrive 공유폴더 연동)
공유폴더 `BX사업본부 - General / 99. 기타 / 사업지원팀 / 계약 진행 현황` 의 `매입 계약 진행 현황.xlsx` 를 Claude 예약 작업이
평일 아침에 읽어 `data.js` 를 갱신하고, **내용이 바뀌었을 때만** GitHub 와 공유 페이지에 반영합니다.

- 변환은 `scripts/build_data.py` 가 합니다. 열 이름·날짜·표시값(O / X / 각서 대체)을 검사하고, 이상하면 **갱신하지 않고** 멈춥니다.
- 엑셀의 **열 순서·열 이름·헤더 2행 구조는 바꾸지 마세요.** 바뀌면 자동 갱신이 중단됩니다.
- 바로 반영하고 싶으면 Claude 에게 "대시보드 업데이트해줘" 라고 요청하면 됩니다.
- 수동 확인: `python3 scripts/build_data.py 파일.xlsx --dry-run`

## 엑셀 불러오기 (수동 · 임시 보기)
화면 오른쪽 위 **엑셀 불러오기** 버튼으로 엑셀(.xlsx)을 골라 바로 대시보드에 띄워 볼 수 있습니다.

- **누른 사람의 브라우저에서만 보입니다.** 다른 직원 화면과 저장소(`data.js`)는 바뀌지 않습니다. 새로고침하면 공유 데이터로 돌아가고, 배너의 **공유 데이터로 되돌리기** 로도 돌아갑니다.
- 파일은 서버로 전송되지 않고 브라우저 안에서만 읽습니다(`vendor/xlsx.mini.min.js`, SheetJS, Apache-2.0).
- 열 구조 검사·날짜/표시값 검사는 `scripts/build_data.py` 와 같은 규칙입니다. 구조가 다르면 불러오지 않고 이유를 알려줍니다. 날짜 형식이 이상한 정도의 문제는 경고만 표시하고 불러옵니다.
- 모든 직원에게 반영하려면 자동 갱신을 기다리거나 Claude 에게 "대시보드 업데이트해줘" 라고 요청하세요.

## 현재 상태 판정 규칙
엑셀의 계약 단계 열(법무검토 요청 → 계약 품의 → 계약서 송부 → 계약서 회수 → 계약보증증권) 중
**가장 멀리 완료(O 또는 '각서 대체')된 단계**를 기준으로 합니다.

| 상태 | 조건 |
|---|---|
| 법무검토 · 품의 전 | 법무검토까지만 했거나 아무것도 없음 |
| 품의 완료 · 송부 대기 | 계약 품의 완료 |
| 송부 완료 · 회수 대기 | 계약서 송부 완료 |
| 회수 완료 · 보증증권 대기 | 계약서 회수 완료 |
| 체결 완료 | 계약보증증권까지 완료 |
| 홀딩 | 비고에 '홀딩' 이 들어 있음 (다른 단계보다 우선) |

셀에 `X` 가 있으면 "확인 필요"로 표시됩니다.

## 디자인 토큰
색상·간격·글자 크기·라운드는 `index.html` 맨 위 `<style>`의 `:root` CSS 변수로 관리합니다. Dark 모드는 같은 변수 이름에 다른 값을 넣어 정의합니다.

| 구분 | 변수 | 비고 |
|---|---|---|
| 상태 색 | `--done` / `--progress` / `--hold` / `--danger` | 체결 완료 / 진행 중 / 홀딩 / 확인 필요 (의미 고정) |
| 단계 램프 | `--st-1` ~ `--st-5` | 1단계(연한 블루) → 체결 완료(짙은 블루) |
| 간격 | `--sp-1` ~ `--sp-8` | 4px 단위 |
| 글자 | `--fs-title` `--fs-section` `--fs-kpi` `--fs-body` `--fs-sub` `--fs-meta` | Pretendard Variable 사용 |

## 파일 구성
- `index.html` : 대시보드 화면
- `data.js` : 엑셀에서 변환된 데이터 (자동 생성)
- `scripts/build_data.py` : 엑셀(.xlsx) 또는 탭 구분 텍스트(.tsv) → `data.js` 변환·검증 스크립트
- `fonts/` : Pretendard Variable 글꼴 (SIL OFL 1.1 라이선스, 같은 폴더의 라이선스 파일 참고)
- `vendor/` : 엑셀 불러오기용 SheetJS (Apache-2.0, 라이선스 파일 포함)

## 실시간 자동 반영 (엑셀 저장 → 대시보드, AI 미사용·무료)

```
직원이 엑셀 저장 → OneDrive 동기화 → [내 PC] watcher.py 가 변경 감지·검증 → Cloudflare KV
→ Cloudflare Pages Function(/api/data, 로그인 보호) → 대시보드가 30초마다 확인해 변경 시에만 다시 그림
```

- 계약 데이터는 정적 파일·GitHub 어디에도 없고, 로그인(Cloudflare Access)을 통과해야만 `/api/data` 로 받을 수 있습니다.
- `scripts/make_dist.py` 로 만든 `dist/` 에는 `data.js` 가 빈 껍데기로만 들어갑니다.
- 반영 시간: OneDrive 동기화(수 초~수십 초) + 감시 주기 5초 + KV 전파(최대 약 60초) + 화면 확인 30초 → 보통 1~2분.
- 이 PC 가 꺼져 있거나 OneDrive 동기화가 멈추면 반영이 멈춥니다(화면에는 마지막 정상 데이터 + 안내 표시).
- 설정 순서는 `watcher/SETUP.md` 참고.
